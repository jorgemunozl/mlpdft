# QE campaign 2026-11 (study design C)

Ready-to-submit SLURM jobs for the new DFT data. Plan, decision rules and costs:
[`assets/research/datasets/shift-ladder-40ry/PLAN.md`](../../research/datasets/shift-ladder-40ry/PLAN.md).
Every input is generated by `src/mlpdft/utils/make_qe_campaign.py`; regenerate
rather than edit by hand.

All settings match the existing 40 Ry runs (PBE, PSLibrary 1.0.0 PAW, 40/320 Ry,
3×3×3 k-points, conv_thr 1e-8, dt = 10 a.u., QE 7.4 on 48 cores with `-nk 2`).
Only two things change: the thermostat uses `nraise = 100`, and MD starts from
the ideal lattice with independent random displacements.

## Submit

```bash
# 1. copy this folder to the cluster, then:
cp config.env.example config.env      # fill in account, pseudopotential folder, scratch
./submit.sh stage1_pilot              # 2 jobs, ~18 h each (30 h requested)
./submit.sh stage2_cutoff             # 4 jobs, 3-9 h requested
```

`ESPRESSO_PSEUDO` must point at the **original** `Li.pbe-sl-kjpaw_psl.1.0.0.UPF`
and `F.pbe-n-kjpaw_psl.1.0.0.UPF` used for the 40 Ry runs. Each job compares the
MD5 sums QE prints at start-up with those runs (Li `d2f1e9ef…`, F `48ea186a…`)
and stops with exit code 3 and a message in `slurm.e*` if they differ. The
copies under `assets/quantum_expresso/pseudo/` are QE-rewritten files with
different checksums; do not use them.

Stage 3 (bulk replicas) and stage 4 (optional F-doped replicas) are generated
after the pilot has chosen the thermostat:

```bash
python3 src/mlpdft/utils/make_qe_campaign.py --stage replicas --env bulk_LiF \
  --thermostat <winner> --seeds 103 104 105 106 107 \
  --dataset-root /home/jorge/project/mlpdft/dataset --out assets/quantum_expresso/campaign-2026-11
./submit.sh stage3_replicas_bulk_LiF
```

## If a job hits its time limit

`max_seconds` stops pw.x cleanly one hour before the SLURM limit. To continue,
set `restart_mode = 'restart'` in that job's `pw.in` and resubmit the same
folder. QE resumes from `$SCRATCH_BASE/<stage>/<job>`, and the job writes
`pw.restart1.out` (then `pw.restart2.out`, and so on), so `pw.out` is never
overwritten. The cutoff jobs skip every single point that already finished.
